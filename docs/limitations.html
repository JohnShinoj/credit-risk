Limitations, reproduction, AI use and citations

Limitations

  1. No loan dates. We cannot study changes over time or link each loan to the economy when it was issued, as the proposal planned. Macro data was used for a plausibility check instead, with an inferred benchmark (average US prime rate over the years that fit the data).
  2. How the grade is produced is not documented. Pipeline A, our main pricing pipeline, assumes the grade is available when someone applies (for example a shared credit rating). If the grade is only assigned by this lender after its own assessment, Pipeline A applies only after that step, and Pipeline B is the realistic setting for new applicants. Pipeline A's rate accuracy (R² 0.91) also reflects this lender's own pricing and may be lower for other lenders.
  3. Country not documented. US lending is assumed from the data's structure; the World Bank comparison depends on that.
  4. Possibly partly simulated data. Rules without exceptions (100%-default groups, no past defaults in grades A–B) and extreme default rates suggest the scores may be higher than on real loans.
  5. Only approved loans. The data contains loans that were granted; we never see rejected applicants (selection bias / reject inference), so the models learn from an already-filtered population.
  6. One dataset. Performance on other lenders, countries or periods is untested. A direct check on another lender (e.g. Lending Club) was not possible because key inputs such as age are missing there.
  7. Information ceiling for newcomers. Without credit-file information the rate can only be estimated to about ±2.7 pp.
  8. Method details. SMOTE was applied after one-hot encoding, so it interpolates categories (SMOTENC would be the cleaner variant); it never improved F1 here. The RBF SVM in Pipelines A and B was tuned on an 8,000-row subset only. The forest searches were randomized (15 combinations), not exhaustive.
  9. Correlation, not causation. The models show which applicants defaulted, not what causes default; in particular, a lower interest rate would not make a risky applicant safer in these models.

Reproduce

Repository: https://github.com/JohnShinoj/credit-risk. Setup and run steps are in the README. All random choices use seed 42; the train/test split is created once in notebook 01 and saved.

NotebookWhat it does
01_clean_split.ipynbdownload (kagglehub), cleaning, stratified 80/20 split
02_probability_of_default.ipynbReference: logistic regression, SMOTE, cutoff tuning, linear and RBF SVM, C/γ grid search
03_decision_trees.ipynbReference: decision tree (depth curve, tuning, readable tree)
04_probability_of_default.ipynbReference: calibrated PD for every model
05_random_forest.ipynbReference: bagging vs Random Forest, tuning, importance
06_applicant_only_models.ipynbPipeline B: every model without rate and grade, calibrated PD
07_interest_rate_regression.ipynbPipeline B: interest-rate regression, gradient boosting, two-stage grade model
08_graded_applicant_models.ipynbPipeline A: every model with grade but no rate, calibrated PD
09_interest_rate_with_grade.ipynbPipeline A: interest-rate regression with grade
10_results_summary.ipynball validation results in one place
11_final_test.ipynbfinal test set (used once), error analysis
12_macro_check.ipynbWorld Bank API check of the interest rates

This website's data is exported from the notebooks' saved outputs by src/export_site_data.py.

AI-use disclosure

Tool used: Claude (Anthropic), model Claude Opus 5.5, through the Claude Code desktop app, 7–17 November 2026.

What I did myself. Chose the topic and wrote the research questions and project proposal (data plan, baseline and candidate methods, evaluation plan). Made the design decisions during the project: working step by step; the three settings (rate + grade known, grade known, newcomer); which models and hyperparameters to tune; keeping the decision tree as a final-model candidate; excluding the grade from newcomer pricing; trimming the tree and forest experiments; deferring SMOTENC; the World Bank check. Reviewed every step's code and results, ran the notebooks, asked questions until I understood each method (cross-validation, SMOTE, cutoff tuning, calibration, Brier score, bagging, regression metrics), and approved each change before it was made.

What the AI assistant did. Wrote most of the Python code in the notebooks and in src/ following my instructions and approvals; explained the theory behind each method and proposed options that I chose between; ran the notebooks to check they worked and found and fixed errors (for example a leakage risk when using PD as an input to the rate model, and a conclusion about Pipeline B that the data contradicted); drafted the text of this website and the README, which I reviewed and edited.

How I checked it. Every number on this site comes from the notebooks in the repository and can be reproduced by running them. The test set was used once, after all choices were frozen (notebook 11). All conclusions, and any errors, are my responsibility.
