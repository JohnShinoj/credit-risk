Method

How the data is prepared, why, and which models were compared, for default prediction and for interest-rate prediction.

The three settings compared on this site (they differ only in what is known when the decision is made):
Reference a loan that is already priced: the lender's grade and interest rate are both known.
Pipeline A a graded applicant: the lender has assigned a grade (A–G), the interest rate is not set yet.
Pipeline B a newcomer: no grade and no rate, only what the applicant tells us.

Preprocessing, and why

StepApplied toWhy
Median imputationemployment length, interest rate (where it is an input)fills gaps without being pulled by extreme values (income and loan amounts are right-skewed)
Standardisation (mean 0, SD 1)numeric columnsputs income (thousands) and age (tens) on the same scale, which logistic regression and SVMs need; harmless for trees
One-hot encodinghome ownership, loan intent, past default, gradeturns categories into 0/1 columns without inventing a false order (e.g. "OWN = 2 × RENT")
SMOTE (optional)training folds onlycreates synthetic defaulters to rebalance the classes; compared with and without (see below)
Leak-free by construction. Every step that learns from data (the medians, the means and SDs, the categories, SMOTE) sits inside a scikit-learn / imbalanced-learn Pipeline. In every cross-validation round it is learned from the four training folds only and then applied to the validation fold; at the end it is learned from the training set only and applied to the test set. SMOTE is applied only when fitting, never to a validation or test fold, so those always keep the real 22% default rate.
one cross-validation round (repeated 5 times, each fold used once for validation)

Logistic regression and the SVMs were run with and without SMOTE. Trees and forests were run without it, because SMOTE never improved F1 for any model once the decision cutoff was tuned (see Result analysis).

From score to probability of default

A good PD must mean what it says: among applicants given PD 0.30, about 30% should default. Each model's scores were turned into PDs with three methods: the model's own probability, Platt scaling (an S-shaped curve) and isotonic regression (a flexible increasing step function). The mapping is fitted by cross-fitting: the mapping applied to a fold never sees that fold's outcomes. The version with the lowest Brier score was kept (04_probability_of_default.ipynb, 06_applicant_only_models.ipynb, 08_graded_applicant_models.ipynb).

Why the rate is never an input when predicting the rate. A PD model that used the interest rate, fed into a model that predicts the interest rate, would leak the answer. So Pipelines A and B use PD models that never see the rate, and the PD used to train the rate model is out-of-fold (each applicant's PD came from a model that did not train on them), so it behaves like a real newcomer's PD.
